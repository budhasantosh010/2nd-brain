# RESTRUCTURING — Self-Maintenance Without Meaning Loss

The brain should continuously detect structural friction so the user does not manually reorganize folders.

## Monitor

Track:

- duplicate concept candidates;
- orphan knowledge;
- oversized topic clusters;
- poorly connected but frequently retrieved knowledge;
- retrieval failures and unanswered questions;
- repeated ambiguous classifications;
- stale projects and stale operational state;
- excessive folder depth;
- broken relationships/links;
- unused generated maps;
- frequent query topics that suggest missing maps/indexes.

## Automatic restructuring

Generated/disposable structures may change automatically: semantic indexes, FTS, generated Maps, dashboards, ranking caches, and similar views. Rebuilding them must not alter canonical meaning.

## Staged restructuring

Concept merges, canonical mass moves, hierarchy changes, identity reinterpretation, or other meaning-changing reorganization create a proposal under `12 Staging/Restructuring`. The proposal includes affected paths, evidence, expected retrieval benefit, risks, and rollback.

## No silent deletion

Restructuring must not delete old knowledge merely because it appears stale or duplicate. Supersession, archive, merge provenance, or explicit human authorization preserves history and reversibility.
